# M5 WebRTC SDK m150.7871.04: exact publisher AAR security-source audit

Date: 2026-11-03. Scope: **original, full, unprefixed** Android AAR, not the Maven classfile-header-stamped copy or codec-stripped variant. Parent #88; work performed in existing Draft PR #172, not production.

## Disposition: SECURITY REJECT — do not integrate or ship v150.7871.04

**Exact source + producer archive + binary identity have been linked.** The verified, publisher-built ARM64 JNI library is delivered from a native fork snapshot whose source contains **five directly relevant unpatched vulnerability source patterns**, including audio/SDP-transceiver control-flow defects. Finding the old vulnerable source and its compiled WebRTC component is sufficient to **reject this candidate**, even though the stripped ELF prevents a line-by-line binary exploitation demonstration. Do **not** say that each CVE is proven exploitable on Android merely from a Chrome advisory.

**Scope note:** CVE identifiers reference public Chrome/WebRTC advisories; Chrome version thresholds alone do not establish Android reachability. Defect source signatures, publisher patch scope, full JNI package composition and original producer AAR identity provide independent reasons to block this exact binary from a high-trust communications app, even without generating attack traffic. The source repo checkout is independently exact, but the original ARM64 binary has no complete internal symbol/debug map; **individual vulnerable instructions and exploitability have NOT been proved**. Marking them unpatched **in exact source** is a stronger and more defensible statement than pretending the ELF has been source-level decompiled.
